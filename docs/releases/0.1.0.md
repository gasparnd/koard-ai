# Koard 0.1.0

First installable release, focused on native OpenCode conversations. Local
packages are prepared before publication; the download location below becomes
available only after the GitHub release is published.

## Install a package

Download your archive and `SHA256SUMS` from
https://github.com/gasparnd/koard-ai/releases/tag/v0.1.0.
Choose `darwin` for macOS or `linux`, and `arm64` or `amd64` for your CPU
(`uname -m`: `arm64`/`aarch64` or `x86_64`). No Go installation is needed.

Example for Apple Silicon, from the download directory:

```sh
grep '  koard_0.1.0_darwin_arm64.tar.gz$' SHA256SUMS | shasum -a 256 -c -
mkdir koard-0.1.0
tar -xzf koard_0.1.0_darwin_arm64.tar.gz -C koard-0.1.0
mkdir -p "$HOME/.local/bin"
test ! -e "$HOME/.local/bin/koard" && install -m 755 koard-0.1.0/koard "$HOME/.local/bin/koard"
export PATH="$HOME/.local/bin:$PATH"
koard --version
```

Expected version: `0.1.0`. On Linux, use `sha256sum -c -` instead of `shasum`.
Do not proceed if checksum verification fails. Existing binaries are not replaced
by this example; review an upgrade separately. Retain the archive's license files.
macOS binaries are not signed or notarized; do not disable OS security checks.

From your target Git project, preview before installation:

```sh
koard native setup --runtime opencode --dry-run
koard native setup --runtime opencode
```

For memory, install Engram 3.7.2 separately, then use `--with-engram` on **both**
commands instead of the assets-only installation. Existing differing config is
never overwritten or merged. OpenCode 2.2.6 and Engram 3.7.2 are the tested pair.
Select the `koard` agent in a fresh OpenCode session; models/authentication remain
your host configuration. Engram inherits its memory environment, not a fresh
isolated store. See the source repository's `docs/opencode-native.md` for effects
and limitations before loading the plugin.

## Evidence and limits

A bounded real-project pilot verified native development with Terra, local
GPT-OSS review, five passing tests, attributed memory writes and retrieval in a
new session. It does not establish reconnect recovery or general unattended
operation. macOS ARM64 receives extracted-package smoke tests; other archives
are cross-build targets, not runtime-tested platforms. Windows, automatic
upgrades/removal, Homebrew/npm distribution and package signing are not included.

Koard is MIT licensed unless a file specifies otherwise. Existing skills retain
their explicit Apache-2.0 declarations. Archives include Engram's unchanged MIT
license/provenance, YAML's Apache-2.0 license/NOTICE and Go's BSD license/PATENTS.

## Rebuild locally

Clone `https://github.com/gasparnd/koard-ai.git` and check out the published
`v0.1.0` tag (or the exact `BUILD.txt` commit). From a clean repository root with
Go 1.27.4 and dependencies already cached, run:

```sh
go test ./...
go vet ./...
mkdir -p dist
GOTOOLCHAIN=local GOWORK=off GOFLAGS= GOPROXY=off go run ./tools/release dist/0.1.0
```

The output directory must not exist. Packaging is offline, refuses dirty
checkouts, emits four normalized archives and `SHA256SUMS`, and removes its new
output directory on failure. Run again into a different directory and compare
checksums before claiming reproducibility. Preserve the exact toolchain and
source commit. `BUILD.txt` is included in each archive. The module name differs
from this repository URL; do not substitute an unverified `go install` command.

Publication is a separate human action: authenticate `gh` for `github.com`,
inspect existing tags/releases, push the approved branch and an annotated
`v0.1.0` tag, then use `gh release create v0.1.0 --verify-tag` with these archives,
checksums and release notes. Never overwrite an existing tag or release asset.
