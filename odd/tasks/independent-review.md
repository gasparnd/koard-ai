# Independent review with bounded correction

Objective: independently review one consented immutable candidate, permit exactly one separately consented proposal-only correction, and remain unable to mutate or deliver the workspace. Branch: `task/2.5-independent-review`. Delivery: `ask-on-risk`, `feature-branch-chain`; forecast: about 1,100 authored changed lines. Test runner: `go test` and `go vet`.

## Specs

1. S1 — Roadmap outcome: "Independent review with a bounded correction lifecycle."
2. S2 — User continuation: "Ya pushee 2.4 vamos con los isguiente." Implement the next governed-orchestration milestone on top of candidate-bound consent.
3. S3 — Documentation requirement: "Recuerda ir creando la documetnacion, donde una persona pueda entender que hace todo esto, cada capa y por que es importante. Recuerda darle importantcia al ensenñar como funciona todo y cada peza". Documentation is part of each behavior unit and must teach the happy path, every layer's responsibility, why each boundary exists, persisted artifacts, invariants, failure modes, and verification.
4. S4 — Correction limit: "Una corrección (Recommended)". One proposal-only correction may produce a revised candidate snapshot and one new independent review attempt. A second correction request terminates as `escalated`; no loop is permitted.
5. S5 — Exact authority: review starts only from a completed workflow with granted review consent for the exact verified workflow, candidate, snapshot, and risk binding. Review mode must be on. Declined, absent, malformed, mismatched, or unverifiable state fails closed before invoking a reviewer.
6. S6 — Provider-neutral contracts: core review requests, results, findings, reviewer identity, attempts, states, and transitions are versioned typed artifacts. Provider behavior stays behind an adapter port; model prose never owns lifecycle transitions.
7. S7 — Independence and capabilities: every review attempt runs in a fresh standalone context, is bound to its exact request and target, and receives only read-only capabilities. Reviewer identity and runtime metadata come from trusted application configuration, not model output.
8. S8 — Lifecycle: persist a single claimed lifecycle with ordered immutable attempt artifacts and a strict current-state record. `correction_required` pauses without invoking a corrector. The exact review target and correction request require a separate immutable `granted` or `declined` correction decision. Supported terminal outcomes are `approved`, `rejected`, `failed`, and `escalated`; concurrent claims, replay ambiguity, cancellation, malformed output, provider failure, or exhausted correction budget fail closed and remain diagnosable.
9. S9 — Non-mutation boundary: this milestone never applies files, changes workspace bytes, commits, pushes, opens pull requests, merges, releases, or creates delivery authority. A correction remains a proposal and immutable snapshot only.
10. S10 — Assumption: expose the vertical through `koard review run --workflow <id>`, `koard review status --workflow <id>`, and `koard review correction <status|grant|decline> --workflow <id>`. Status commands are read-only; `run` executes only the next authorized bounded transition and reports the exact target, state, attempt, verdict, and remaining correction budget.
11. S11 — Public-interface tests cover exact consent/snapshot binding, mode off, approved review, pause before correction, separately granted and declined correction, one correction and re-review, second correction escalation, reviewer independence metadata, read-only capabilities, strict request/result decoding, wrong identities, provider failure, cancellation, concurrent claim, partial persistence, idempotent status, usage, output, exit codes, and absence of workspace mutation.
12. S12 — Update CLI help, README, architecture, focused independent-review guide, documentation index, self-hosting explanation where relevant, and roadmap only when behavior is observable. Run focused race tests, `go test ./...`, `go vet ./...`, `gofmt -l internal cmd`, and `git diff --check`.
